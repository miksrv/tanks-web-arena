## Архитектура

- Одна симуляция боя (`sim`), которая работает и в браузере, и на сервере. Клиент общается с ней через интерфейс `Transport`:
  - `LocalTransport` — симуляция в Web Worker, обмен через `postMessage` (снимки как transferable `ArrayBuffer`). Офлайн, без рангов.
  - `SocketTransport` — та же симуляция на сервере, WebSocket. Ранговый бой.
  - `InProcessTransport` — запасной вариант: прямые вызовы в главном потоке, без сериализации (отладка, проблемы с Worker).
- Npm workspaces: `sim` (без рендера и DOM) / `client` (рендер, HUD, звук, ввод, интерполяция) / `server` (комнаты, матчмейкинг, аккаунты, БД). Границы проверяет компилятор.
- Сервер авторитетный: клиент шлёт только ввод (газ, поворот, точка прицела, выстрел, снаряд, расходник). Невидимые враги в снимок не попадают — честный засвет.
- Карта рассылается как seed; генерация должна быть строго детерминированной.

## Неткод

- Тик: 60 Гц локально, 30 Гц на сервере; снимки 20–30 Гц, только видимые танки (единицы КБ/с на игрока).
- Предсказание своего танка + сверка с сервером (локально можно отключить).
- Интерполяция чужих танков (~100 мс буфер онлайн, меньше локально); визуальная интерполяция своего танка между тиками.
- Компенсация лага при попаданиях: сервер отматывает позиции целей на пинг стрелка.
- Камера и прицел остаются на клиенте и мгновенны; выстрел ждёт ближайшего тика.

## Сервер и деплой

- Один Docker-контейнер Node: WebSocket (`ws`) + раздача статики клиента.
- SQLite на volume: аккаунты, рейтинг, опыт, открытые танки, история боёв.
- Caddy перед контейнером — автоматический HTTPS (страница по https не откроет `ws://`). Всё в `docker-compose`.
- Проверка версии протокола при подключении («обнови страницу»).
- Комната с кодом приглашения или очередь «ждём N секунд → добиваем ботами»; боты живут на сервере.

## Ранги и прогресс (только онлайн)

- Аккаунт: ник + пароль, токен в `localStorage`.
- Опыт за бой (урон, засвет, assist, победа) → открытие веток танков.
- Рейтинг: Glicko-2 или Elo по итогу боя с поправкой на личный вклад (осмысленно и при одном живом игроке).
- Статистика: процент побед, средний урон, медали.

## Нагрузка на клиенте в локальном режиме

Суммарно работы чуть больше (сериализация, интерполяция, вторая копия высот и коллайдеров — несколько МБ), но вся логика — боты, засвет, баллистика, столкновения — уходит из главного потока в Worker. Время кадра в главном потоке уменьшится, микрофризы от пересчёта позиций ботов уйдут.
